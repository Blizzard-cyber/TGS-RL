# A10 工程与 Helm 验收记录

## 结论

2026-09-14，TGS-RL 在单张 NVIDIA A10 的 Kubernetes 测试机上完成工程验收：

- `make gpu-a10-readiness`：`PASSED`；
- A10 Full lifecycle：`PASSED`，真实 `checkpoint → offload → reload → resume`；
- H2 HAMi 双 worker：`PASSED`，两个 worker 共享同一物理 GPU；
- 恢复 NVIDIA Device Plugin 后 E1：`PASSED`；
- 六服务 NVIDIA Helm install 与同 PVC upgrade 两轮 smoke：`PASSED`，共 630 个索引文件哈希全部匹配；
- 最终无测试 Job、ResourceClaimTemplate、ResourceClaim 或 JobRunBundle 残留。

这仍是单节点最小 trainer 的工程验证，不代表完整 veRL 训练、性能收益、MIG、多节点或
GPU Pod/节点/网络故障恢复已经验证。

Helm 最终通过时，控制面、bootstrap 和 workload 镜像均来自上述 commit 构建的不可变 digest。
实装与最终 SHA 复跑过程中共关闭六个部署/重跑缺陷：

1. 新 hardware campaign 与持久化 Gateway 复用旧 idempotency key；
2. Kubernetes 1.35 不支持 `kubectl rollout status deployment --all`；
3. 非 root Scheduler 无法对 root-owned PVC 挂载点执行 `chmod`，helper 状态必须写入独立子目录。
4. cleanup 的 GET→DELETE 间对象可能已被控制器删除；精确 `NotFound` 现在按幂等成功处理，
   UID/resourceVersion Conflict 和其他错误仍 fail closed；
5. 被硬件 driver 先清理的 Bundle 会留下持久 observation registration，97 个孤儿 watcher
   曾形成 O(N²) ledger 读写并拖慢 Trace；Operator 现在启动时原子剪枝、运行中按 Bundle
   absence 回收；
6. Gateway `/health` 即使后端 degraded 也返回 HTTP 200；Helm smoke 现在要求 Job Controller、
   Scheduler、Runtime、Experiment 四个 gRPC 依赖全部 serving 后才启动 A10 lifecycle。

最终 `68f5aea` 是包含全部修复的干净提交，不再依赖“旧镜像 + 未提交工作树补丁”解释。
