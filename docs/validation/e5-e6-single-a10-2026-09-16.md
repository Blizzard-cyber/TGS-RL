# E6 与 E5-STATIC 单 A10 实验记录

## 结论

2026-09-16，TGS-RL 在单张 NVIDIA A10 上完成两项真实硬件实验：

- E6 lifecycle 动作代价：`701e11b` pilot 用于冻结阈值，`13d0f34` 独立确认运行的
  campaign E6 状态为 `PASSED`，证据级别 `GPU_SINGLE_NODE`，不是模拟运行；
- E5-STATIC 静态份额共置干扰 pilot：独立执行报告为 `PASSED`，证据级别
  `GPU_SINGLE_NODE`，不是模拟运行；
- 本轮 E6 与 E5-STATIC 数据均作为 pilot 完成阈值标定；
- E6 已由阈值冻结后的干净提交 `13d0f34` 独立确认，正式 campaign 中 E6 为 `PASSED`；
- E5-STATIC 只验证固定 HAMi 份额下的错峰/共置对照，不替代正式 E5 的在线
  `set_share` / `set_priority`。

原始证据保留在 A10 测试机 `.cache/tgsrl/`，本页只记录可公开复核的摘要和哈希。

## E6 结果

E6 通过 scoped worker registry 对同一个真实 CUDA worker 依次执行：

```text
pause -> checkpoint -> offload -> reload -> resume
```

| 指标 | Variant 结果 |
|---|---:|
| action success rate | 1.0 |
| pause latency | 45.042 ms |
| checkpoint latency | 704.530 ms |
| reload latency | 260.322 ms |
| end-to-end iteration P50 | 10219.665 ms |
| scheduling latency P95 | 2172.178 ms |
| throughput | 44.990 items/s |

原始 Trace 中五类动作均有结构化请求、receipt 和状态转换。代表性 offload receipt
显示 PyTorch allocated bytes 从 `549584896` 降至 `8519680`；对应 reload receipt
再从 `8519680` 恢复到 `549584896`。checkpoint 存在、offload 后显存下降、reload
后显存恢复、resume 后 worker ready 均由硬件证据校验。

E6 pilot 独立 report 为 `PASSED`。三轮 measurement 的最大值分别为 pause
`46.907 ms`、checkpoint `711.072 ms`、reload `301.490 ms`。采用“最大值乘
`1.25` 后向上取工程档位”的规则，正式门槛冻结为：

| 规则 | Pilot 最大值 | 乘 1.25 | 冻结阈值 |
|---|---:|---:|---:|
| pause | 46.907 ms | 58.634 ms | 60 ms |
| checkpoint | 711.072 ms | 888.840 ms | 900 ms |
| reload | 301.490 ms | 376.862 ms | 400 ms |

机器可读决策保存在 `configs/gates/e6-action-cost-calibration.json`。该 pilot 不再用于
最终验收；阈值冻结后的提交 `13d0f34b23c581b73d32ab959d6db6bb9c83bfd0`
随后完成独立确认：

| 规则 | 冻结阈值 | 确认运行 | 结果 |
|---|---:|---:|---|
| pause | 60 ms | 54.479 ms | PASSED |
| checkpoint | 900 ms | 695.910 ms | PASSED |
| reload | 400 ms | 272.408 ms | PASSED |

确认运行仍为 1 次 warmup、baseline/variant 各 3 次 measurement；每轮均包含
pause/checkpoint/offload/reload/resume 五类 receipt。三次 offload 的 allocated bytes
均从 `549584896` 降到 `8519680`，三次 reload 均恢复到 `549584896`。E6 在
E1–E8 campaign 中的正式状态为 `PASSED`。

## E5-STATIC 结果

E5-STATIC 对同一张 A10 上的两个 worker 使用固定 HAMi 配额：

```text
每个 worker: 40% core, 9211 MiB GPU memory
总 core 份额: 80%
baseline: 两个 worker 错峰
variant: 两个 worker 并发
```

Scheduler UUID、HAMi allocation UUID 和 worker 可见 UUID 均为同一个物理 A10 UUID，
两个 worker 的 sandbox、binding 和 pending-unit 身份互不相同。

| 指标 | Baseline | Variant |
|---|---:|---:|
| throughput | 33.124 items/s | 25.609 items/s |
| worker overlap | 0 ms | 8570.544 ms |
| concurrent worker count | 0 | 2 |
| aggregate accelerator share | 0 | 0.8 |
| end-to-end iteration P50 | 10247.415 ms | 10343.285 ms |

由逐 worker 吞吐推导的 `interference_ratio` 为 `0.229306`。这只是当前代表性
CUDA tensor workload、单卡、固定 40% 份额下的首轮观测值；未做置信区间、跨日重复、
完整 veRL workload 或阈值评审，不能外推为生产性能结论。

E5-STATIC pilot 三轮干扰率为 `0.222769/0.218472/0.246678`。采用与 E6 相同的
“最大值乘 `1.25` 后向上取工程档位”方法：

| Pilot 最大值 | 乘 1.25 | 冻结阈值 |
|---:|---:|---:|
| 0.246678 | 0.308348 | 0.32 |

机器可读决策保存在 `configs/gates/e5-static-interference-calibration.json`。该 pilot
不再用于最终验收；必须由后续干净提交独立确认。正式 E5 仍为 `NOT_RUN`。

## 实机发现与修复

实机执行发现并关闭了两个配置问题：

1. `Dockerfile.gpu-smoke` 已引用新实验脚本，但 `.dockerignore` 未放行该文件，首次构建在
   `COPY scripts/gpu-experiment-workload.py` 失败；`701e11b` 增加白名单和治理测试。
2. E5-STATIC 初始每 worker 请求 `12 GiB`，两个 worker 合计超过 A10 的 23028 MiB，
   Scheduler 正确返回 `NO_CANDIDATE`；`3c9147c` 将调度资源请求对齐已验证 H2 合同的
   每 worker `8 GiB`，实际 HAMi GPU memory 配额仍按 40% 回读为 9211 MiB。

首次 E5-STATIC 失败尝试保留在测试机
`.cache/tgsrl/e5-e6-run-701e11b/e5-static-failed-12g/`。HAMi 控制面首次重启还发现
24 小时 scoped Operator token 已过期；重新执行 `make gpu-configure-access` 并通过 RBAC
`can-i` 后恢复，不将环境凭据问题计入实验结果。
